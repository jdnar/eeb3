5.1 Why several tables?

To store data efficiently, related information is often spread across multiple tables. Imagine a magazine company where customers have different subscriptions. One huge table could hold: order_id, customer_id, customer_name, customer_address, subscription_id, subscription_description, subscription_monthly_price, subscription_length and purchase_date.

But much of that information would be repeated: a customer with several subscriptions would repeat their name and address every time, and a popular subscription would repeat its price and description for every order. The table becomes big and unmanageable. Instead we split the data into three tables:

TableColumns
ordersorder_id, customer_id, subscription_id, purchase_date
subscriptionssubscription_id, description, price_per_month, subscription_length
customerscustomer_id, customer_name, address

5.2 Combining tables manually

Looking only at orders, you cannot tell what happened in each order. Consult the other tables and the picture is complete. Take the order with order_id 2, bought by the customer with customer_id 2: to find the name, look in customers for customer_id 2 — Jane Doe, who lives at 456 Park Ave. This matching process is called joining two tables.

5.3 Combining tables with SQL: JOIN

Matching by hand is slow. SQL does it with JOIN. To combine orders and customers:

SELECT *
FROM orders
JOIN customers
  ON orders.customer_id = customers.customer_id;
  1. The first line selects all columns of the combined table (you may pick specific ones instead).
  2. The second line names the first table, orders.
  3. The third line uses JOIN to say we want to combine orders with customers.
  4. The fourth line says how to combine them: match customer_id in orders with customer_id in customers.
Important: Column names are often repeated across tables, so write table_name.column_name to keep requests unambiguous — in ON, in SELECT, and anywhere else you refer to a column.
SELECT orders.order_id,
   customers.customer_name
FROM orders
JOIN customers
  ON orders.customer_id = customers.customer_id;

5.4 Inner joins

A simple JOIN is often called an inner join: the result includes only the rows that match the ON condition. If the customers table were out of date and lacked customer 11, any order from customer 11 would simply disappear from the joined result.

Picture an inner join of two tables on table1.c2 = table2.c2: the rows with matching c2 values appear in the result; the non-matching rows do not.

  2. Join newspaper and online on their id columns (the unique ID of the subscriber). How many rows does the result have?

5.5 Left joins

What if we want to combine two tables and keep the rows that have no match? LEFT JOIN keeps every row of the first (left) table, whether or not a matching row exists in the second (right) table. Where there is no match, the columns from the right table are filled with NULL.

SELECT *
FROM table1
LEFT JOIN table2
  ON table1.c2 = table2.c2;
  1. The first line selects all columns from both tables.
  2. The second line names table1, the "left" table.
  3. The third line performs a LEFT JOIN on table2, the "right" table.
  4. The fourth line says how to match: values in column c2.

5.6 Primary key vs foreign key

In the magazine example, each table has a column that uniquely identifies its rows: order_id in orders, subscription_id in subscriptions and customer_id in customers. These are primary keys. A primary key has these requirements:

  • None of its values can be NULL.
  • Each value must be unique (no two customers can share a customer_id).
  • A table cannot have more than one primary key column.

Look again at orders: it contains customer_id (the primary key of customers) and subscription_id (the primary key of subscriptions). When the primary key of one table appears in another table, it is called a foreign key. So customer_id is a primary key in customers but a foreign key in orders.

In practice the primary key is usually just called id, while foreign keys get more descriptive names. The most common kind of join links a foreign key in one table with the primary key of another — for instance joining orders and customers on customer_id.

5.7 CROSS JOIN

So far we matched rows that share information. Sometimes we just want to combine every row of one table with every row of another — for instance, all possible outfits from a table of shirts and a table of pants:

SELECT shirts.shirt_color,
   pants.pants_color
FROM shirts
CROSS JOIN pants;

Notice that a cross join needs no ON clause: you are not joining on any column. With 3 shirts (white, grey, olive) and 2 pants (light denim, black) you get 3 × 2 = 6 combinations. A more common use is comparing each row of a table to a list of values.

Exercise 6

The newspaper table has two more columns: start_month (first month the customer subscribed to the print newspaper, e.g. 2 for February) and end_month (the last month). How many users were subscribed during each month of the year?

  3. Add a WHERE to the cross join with two conditions, start_month <= month and end_month >= month. This selects all months in which a user was subscribed.

5.8 UNION

Sometimes we want to stack one dataset on top of another. UNION does exactly that, provided both tables have the same columns.

SELECT *
FROM table1
UNION
SELECT *
FROM table2;
Important: SQL has strict rules for appending data: the tables must have the same number of columns, and the columns must have the same data types in the same order as in the first table.

5.9 WITH

Often we want to combine two tables when one of them is the result of another calculation. Suppose marketing wants to know how many magazines each customer subscribes to. Easy with orders:

SELECT customer_id,
   COUNT(subscription_id) AS 'subscriptions'
FROM orders
GROUP BY customer_id;

But a customer_id is not very useful to marketing — they want the name. We need to join this result with customers. A WITH clause lets us do that:

WITH previous_results AS (
   SELECT ...
   ...
)
SELECT *
FROM previous_results
JOIN customers
  ON _____ = _____;
  • WITH lets us run a separate query first (here, counting each customer's subscriptions).
  • previous_results is the alias used to refer to the columns produced by the query inside the parentheses.
  • We can then use that temporary table like any other — for example, joining it with another table.

In short: you put a whole first query inside parentheses, give it a name, and then use that name as if it were a table in a new query.

Exercise 8

Place the query below inside a WITH statement (in parentheses) named previous_query. Then join the temporary table with customers and select customers.customer_name and previous_query.subscriptions.

SELECT customer_id,
   COUNT(subscription_id) AS 'subscriptions'
